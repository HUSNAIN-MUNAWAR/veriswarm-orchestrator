# Methodology

VeriSwarm evaluates the combined workflow rather than treating an agent response as success. A run has a scoped workspace, a planned task DAG, provider events, independent verification, oversight decisions, and a persisted terminal decision.

## Current executable profile

`npm run benchmark` executes 60 isolated development runs: 12 independently copied order-idempotency cases across five scheduler strategies. The provider is `MockAgentProvider`, which performs a deterministic fixture edit only for the codex-worker role. Every outcome is generated by the scheduler and verifier; no success-rate table is injected into the report.

The task suite also declares seven held-out problem families: concurrency, authorization, API correctness, workflow state, data consistency, failure recovery, and workspace scope. They are intentionally reported as `NOT EVALUATED` until distinct fixtures and executable contracts exist.

## Outcome definition

A run is verified successful only when the independent command exits with code zero, all required files remain present, and every changed/deleted/renamed file is inside the allowed change set. The worker's final text is stored as an artifact but does not determine the decision.

## Qualification

The evaluator computes a one-sided Wilson lower bound for the development outcomes. It does not issue a qualification claim when held-out evidence is absent. Review rate, tool calls, estimated cost, recovery events, and provider identity remain visible alongside success.
